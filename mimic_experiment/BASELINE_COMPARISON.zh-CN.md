# MIMIC-IV：四个 baseline 与 latent2x both 的比较方案

## 1. 从已有 MIMIC 任务继续比较

现有实验已经将 MIMIC-IV 3.1 整理为患者的小时级纵向记录，并完成 latent2x both 的训练。本次在同一数据、同一预测任务上训练 HealthFlux-KL、ODE-AE、ODE-RNN 和 Latent ODE。

主要问题是：**给定患者入住 ICU 后前24小时的资料，哪种模型能更准确地预测之后24小时的生理指标与GCS？**

[实时横向比较表](results/baselines_single_cuda/summary.md)汇总五个模型的参数量、训练进度、原始目标误差、原始单位误差及不同预测范围的结果。

## 2. 所有模型使用哪些相同条件

### 2.1 同一批患者与字段

直接读取 `/data/MIMIC/derived/latentode_iv31/dataset.pkl`，版本为 `chronology_v2`。这份缓存已检查首次ICU住院、成人年龄、前48小时住院及存活时间、前后两天的观测支持。

| 内容 | 本次设置 |
|---|---|
| 训练患者 | 21,517 |
| 验证患者 | 4,649 |
| 测试患者 | 4,536 |
| 观测窗口 | 首次ICU住院的前48小时 |
| 原始字段 | 27个数值字段、3个GCS类别字段、性别，共31项 |
| 展开后的目标维度 | 44 |
| 时间 | 按可用时间聚合的小时窗口，保留真实小时间隔 |
| 归一化 | 使用训练患者的min-max参数，验证及测试使用相同参数 |
| 缺失处理 | 保留掩码，按字段决定输入和评分 |

各模型也获得相同的年龄资料。年龄以年表示，与小时制的ODE时钟分别提供。

### 2.2 同一套历史截止任务

训练时，每位患者每轮从可用的6、12、18、24小时历史截止点中选择一个。选择由患者编号、seed和轮次确定，所有模型使用同一选择规则。每轮患者顺序也使用同一稳定排列。

主要验证和测试固定使用前24小时历史。未来真实值留作评价标签。补充测试使用6小时、12小时历史，分别预测到第48小时，并报告有相应观测支持的患者数。

### 2.3 相同的优化预算

| 设置 | 取值 |
|---|---|
| 随机种子 | 0 |
| 每次优化的有效batch | 128位患者 |
| 优化器 | Adam |
| 初始学习率 | 0.003 |
| 学习率衰减 | 每步使用 `0.97^(step/2000)` 比例 |
| 输入观测dropout | 0.1 |
| 梯度范数上限 | 10 |
| 最大 / 最少轮次 | 300 / 50 |
| 早停 | 验证整体误差连续40轮没有改善 |
| 最佳检查点 | 验证整体数据误差最小的检查点 |

每个模型单卡训练。一次128人的优化批次按四组处理，在本卡累积梯度；每组最多32人。每个字段的误差都除以整个128人批次中的有效观测数。KL按对应患者数或有效节点数汇总，ODE参数L2每个优化步骤计一次。

这样，模型之间比较的是相同数量患者带来的优化步骤。最后不足128人的批次按实际观测数和实际人数计算。

## 3. 四个 baseline 如何接入这个任务

### 3.1 HealthFlux-KL

沿用已有 HealthFlux 实现：256维确定性状态、128维随机状态，年龄和静态背景条件、Gaussian先验与后验、GRU更新、LayerNorm，以及模态注意力汇聚。

ICU输入按以下三组组织：

| 组别 | 字段 |
|---|---|
| 生命体征 | 心率、收缩压、舒张压、平均动脉压、呼吸频率、SpO₂、体温、FiO₂、体重 |
| 化验 | 血糖、肾功能、电解质、血常规、乳酸和血气，共18项 |
| GCS | 睁眼、运动、语言反应 |

同一时刻的有效组经各自编码器处理，再通过注意力形成观测表示。性别进入首次历史记录的静态背景；年龄通过独立年龄编码提供。当前31字段中没有诊断事件，因此每个有有效观测的历史时刻使用一次观测后验更新。

动力学按小时推进，年龄条件始终以年提供。RK4使用名义1小时子步，每个记录间隔最多4个子步。这个时间尺度使模型学习 ICU 数小时内的状态变化。

未来阶段推进确定性ODE状态，使用随机先验均值组成健康表示，再由44维解码器输出字段预测。历史重构从截止状态向过去积分。KL系数取0.01。

连续输入在模型内部按训练均值和标准差转成z-score，并截断到[-10,10]。监督标签和最终评分继续使用共同的min-max尺度。

HealthFlux的模型公式及实现来源沿用[既有复现记录](../healthflux/README.zh-CN.md)。

### 3.2 ODE-AE

使用原有概率ODE-AE：6维随机潜在状态、16宽MLP和ODE网络。模型从历史末端反向读取记录，在首次观测处形成Gaussian潜在状态，再由独立生成ODE输出轨迹。

INIT接收真实年龄锚点推算值，观测间隔和生成ODE使用小时。训练从后验采样，测试使用后验均值，KL系数为1。

### 3.3 ODE-RNN

沿用原有32维状态、64宽ODE网络和GRU更新。状态按小时演化，在每条记录读入之前先给出该时刻的预测，再用历史观测更新。

年龄作为额外协变量输入GRU，使用“年龄/100”，解码目标仍为44维。训练保留原实现0.5的teacher forcing概率。

未来阶段，每次先经ODE推进并解码，再把模型自己的数值预测及类别概率作为下一次GRU输入。这是该baseline的递归生成路径。

### 3.4 Latent ODE

保留32维随机潜在状态、64维ODE-RNN编码器，以及64宽ODE网络。历史编码器按时间读取记录，形成截止时刻的Gaussian后验；年龄通过额外协变量输入编码GRU。

训练从后验采样，测试使用后验均值。生成从截止状态分别向过去和未来积分，保持后验的实际时间位置。KL系数为1。

### 3.5 各模型训练目标

四个baseline共同的数据项为：

\[
L_{\mathrm{data}}=L_{\mathrm{MSE}}+L_{\mathrm{CE}}.
\]

在数据项之外，保留各模型自己的正则：

| 模型 | KL | ODE参数L2 | weak prior | Jacobian |
|---|---:|---:|---:|---:|
| latent2x both | — | 0.02 | 0.01 | 0.01 |
| HealthFlux-KL | 0.01 × 后验对转移先验KL | 0.02 | — | — |
| ODE-AE | 1 × 后验对标准Gaussian的KL | 0.02 | — | — |
| ODE-RNN | — | 0.02 | — | — |
| Latent ODE | 1 × 后验对标准Gaussian的KL | 0.02 | — | — |

模型容量沿用现有ADNI比较中的各baseline设置，输入输出层按MIMIC字段适配。比较表同时列出总参数与可训练参数，便于结合模型容量阅读结果。

## 4. 如何测试并汇总

### 4.1 统一评价代码

所有新模型调用同一个[单卡评价器](evaluation.py)。它在单卡上依次处理原四卡参考实验的四份固定患者分片，查询批次与参考结果保持一致。

评价器已用完整4,536位测试患者重新计算既有latent2x both检查点，核对历史、未来、整体、6/12/24小时预测范围及各原始单位指标。核对记录位于 `checks/latent_ode/checks/reference_evaluation_check.json`。

历史区间中，ODE-RNN统计当前观测读入前的因果预测，其余模型统计历史条件下的重构。未来区间统一使用截止点之后的真实有效观测。

### 4.2 最终报告的指标

1. 历史区间、未来区间、整体的MSE＋交叉熵。
2. 固定前24小时历史后，未来6、12、24小时的累计误差。
3. 27个数值字段在原始单位下的MAE和RMSE。
4. 各数值字段按训练标准差换算后的MSE，再对字段等权平均。
5. 三项GCS未来分类准确率。
6. 只使用6小时、12小时历史时的未来预测误差及患者数。
7. “保持最近观测值”的同任务结果。

每个模型训练结束后载入最佳检查点，重新核对验证分数，再执行测试。测试标签参与最后的指标汇总。

## 5. 单卡运行安排

| 模型 | 物理GPU | Conda环境 | 并行方式 |
|---|---:|---|---|
| HealthFlux-KL | 0 | healthflux | 单卡，梯度累积 |
| ODE-AE | 1 | ode | 单卡，梯度累积 |
| ODE-RNN | 2 | ode | 单卡，梯度累积 |
| Latent ODE | 3 | ode | 单卡，梯度累积 |

启动命令：

```bash
bash scripts/run_mimic_baselines.sh
```

每条任务依次完成CUDA检查、完整48小时小规模预检查和正式训练。检查会改变未来观测值、未来标签掩码及未来查询时间，分别核对预测隔离和截止状态隔离；还会检查参数梯度和小时制积分。

SwanLab记录四条独立训练曲线。`hardware.json`保存实际物理GPU、模型设备、输入设备、预测设备、参数量及有效批次设置。

## 6. 输出文件

本次输出位于 `mimic_experiment/results/baselines_single_cuda/`。

| 路径 | 内容 |
|---|---|
| `summary.md` | 自动更新的横向比较文档 |
| `comparison.json` | 结构化模型结果与逐字段MAE |
| `configs/` | 四个模型的实际训练配置 |
| `checks/` | CUDA隔离检查、参考评价器核对、小规模完整流程 |
| `healthflux_kl/seed_0/` | HealthFlux-KL训练及测试结果 |
| `ode_ae/seed_0/` | ODE-AE训练及测试结果 |
| `ode_rnn/seed_0/` | ODE-RNN训练及测试结果 |
| `latent_ode/seed_0/` | Latent ODE训练及测试结果 |
| `source_snapshot/` | 本次实际执行源码及SHA256 |
| `queue.json` | 各单卡任务的阶段和进程信息 |

每个模型同时保存 `best.pt` 与 `last.pt`。前者用于最终测试，后者保存最近完整轮次的模型、优化器、学习率和历史，供任务中断后继续运行。已完成的模型会保留，重启入口会继续未完成阶段。
