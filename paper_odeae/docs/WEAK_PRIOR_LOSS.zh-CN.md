# shared_matched 的弱校正前预测约束

## 1. 为什么增加这一组

原 shared_matched 学习一个共享速度场。两次检查之间，患者状态沿 ODE 演化；读到新检查时，UPDATE 再修正状态。原损失监督最终状态生成的历史和未来轨迹，没有直接监督每一次 UPDATE 之前的预测。

因此模型可能依靠观测更新来纠正较大的演化偏差。本实验希望让模型在读入当前检查之前，就能利用此前状态和 ODE 给出更准确的预测。

## 2. 新损失怎样计算

先将上一次更新后的状态沿 ODE 推进到当前检查时间，得到 `z⁻`。在当前观测进入 UPDATE 之前，使用同一个 DECODER 输出预测。然后将这个预测与当前真实检查比较：数值字段计算 MSE，类别字段计算交叉熵。每个字段在有效目标上取平均，再按字段相加。

完整损失为：

```text
原数值重构损失 + 原类别重构损失 + 0.02 × ODE 参数平方和
    + 0.01 ×（校正前数值预测 MSE + 校正前类别预测交叉熵）
```

新增项从第二次历史检查开始计算，让模型先有一次观测可用。首次检查、历史截止点之后的未来区域，以及缺失标签都不参加这项新增损失。原本的历史重构与未来预测损失继续保持。

目标是否有效由真实观测掩码决定，训练时的随机输入丢弃不会把真实标签删除。预测先计算，当前检查随后才进入 UPDATE；新增项可以反向训练 INIT、之前的 UPDATE、共享 ODE 和 DECODER。这里没有要求状态跳变必须很小，也没有要求前后预测相同，以保留吸收新信息的能力。

## 3. 如何与原模型比较

本实验以原 shared_matched 为起点设置，从头训练，仍为 22,545 个参数。收集校正前预测不增加任何网络或参数，权重 λ 固定为 0.01。数据、seed 0、学习率、全局 batch 32、输入丢弃和早停规则均沿用原单卡设置。

λ=0 直接使用此前已完成的单卡 shared_matched，不重新训练对照。按用户要求，新实验也采用单卡，运行在停止 init_4x 后释放的物理 GPU 0 上。GPU 1–3 的其他扩容实验继续运行。

检查点仍按原验证整体误差选择，新损失不会混入检查点选择分数。正式结束后，比较原测试未来预测和整体误差，同时记录新模型的校正前误差，区分“更准确地连续演化”和“只改变训练损失数值”。旧基线没有保存校正前指标，对应位置暂留空。

## 4. 检查和运行记录

CUDA 检查覆盖：当前检查数值变化不会改变读入前预测；首次检查与单次历史没有新增损失；缺失掩码与历史截断生效；新增监督可向各网络传播有限梯度；参数量不变，收集预测本身不改变原生成结果。新增测试与原模型/方向测试共 13 项已通过。

早期尝试的四卡对照检查已取消，仅保留小数据检查记录，没有启动正式 λ=0 重训。本次正式实验另存于 `results/shared_matched_prior_weak_single/`，与这些检查分开。

运行入口：

```bash
bash scripts/run_shared_matched_prior_weak.sh
```

脚本先做单卡小数据训练、验证、检查点重载和测试，成功后自动开始完整训练。模型代码和训练器在启动前保存快照及哈希；物理 GPU、实际张量设备和损失分量写入实验记录。训练接入 SwanLab，增加 `prior_mse`、`prior_cce`、`weighted_prior` 曲线。
