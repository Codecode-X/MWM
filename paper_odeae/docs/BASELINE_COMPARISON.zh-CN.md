# 在 ODE-AE 评测任务上比较 Latent ODE 与 ODE-RNN

## 1. 为什么需要重新训练适配模型

此前的 ADNI 检查点使用 58 维数值输入和训练集 z-score，主要学习未来数值预测。ODE-AE 当前任务使用 40 个字段、min-max 归一化，并要求输出类别概率用于交叉熵评分。输入、输出和归一化不兼容，因此不能把旧检查点直接放入新的评分函数。

本次复用 `src.model` 的 Latent ODE 与 ODE-RNN 网络模块，在相同 ODE-AE 数据和评分合同下重新训练。旧 ADNI 实验和原 ODE-AE 结果保持原样。

## 2. 本次统一哪些条件

所有任务读取同一个 `paper_odeae/cache/local_available.pkl`，共 40 个字段，训练、验证、测试患者分别为 2093、393、414。

训练与评价都枚举每位患者的全部历史截断。训练随机遮挡 10% 的历史字段，目标为完整序列。数值字段先在有效观测上计算 MSE，类别字段计算交叉熵，然后按字段求和。概率模型再加入系数为 1 的 KL；ODE 参数平方和的正则系数为 0.02。

各任务统一使用 seed 0、batch size 32、学习率 0.003、每 2000 更新步衰减 0.97。最多训练 300 轮，至少 50 轮，连续 40 轮验证整体误差不改善后停止。由验证集选择检查点，重载核对后才计算完整测试指标。概率模型用后验均值作为评价初始状态。

## 3. 四张 GPU 分别运行什么

| 物理 GPU | 模型 | 容量组 | 潜在/递归状态维度 | ODE 隐藏层宽度 | Latent ODE 编码隐藏维度 |
|---|---|---|---:|---:|---:|
| 0 | Latent ODE | native | 32 | 64 | 64 |
| 1 | ODE-RNN | native | 32 | 64 | — |
| 2 | Latent ODE | small | 6 | 16 | 16 |
| 3 | ODE-RNN | small | 6 | 16 | — |

native 沿用此前 ADNI 模型容量。small 对齐 ODE-AE 的潜在维度和隐藏层宽度；它仍保留原模型的两层 ODE 隐藏层，因此是维度/宽度对照，不是严格参数量匹配。任务不增加随机种子。

## 4. 模型怎样适配新任务

### Latent ODE

它保留原 ADNI 适配器的正向历史编码，估计历史截止点处的后验。为了覆盖新增的历史重构目标，生成 ODE 先从截止点向过去积分到首次检查，再向前生成完整序列。训练采用采样，评价采用均值。这个截止点锚定方式与 ODE-AE 的反向编码、首次检查锚定构成模型结构差异。

### ODE-RNN

它保留因果自回归结构：先预测当前检查，再读取当前已知观测并更新状态。历史训练时采用 0.5 的 teacher forcing，未来只反馈模型预测。数值反馈使用预测数值，类别反馈使用 softmax 概率；未来目标和目标缺失掩码都不送入状态更新。

因此，ODE-RNN 的历史项属于因果预测，而 ODE-AE 的历史项可以利用截止点之前的全部历史重构过去。评价代码和目标观测一致，但信息使用方式不同。最终比较应先看未来预测误差，再结合历史与整体误差解释。

### 公共处理

原始类别字段展开为独热输入，观测掩码同步展开。解码输出的类别 logits 直接进入交叉熵。沿用既有掩码 GRU、潜在后验、ODE 和解码网络；与本任务无关的二分类头冻结，不参与优化。

两种新模型使用与 ODE-AE 相同的 Tsit5 求解器和容差；保留原 ADNI 适配器以十年为一个单位的相对时间参数化。ODE-AE 使用年。时间单位不改变实际检查时间，但会改变向量场参数及 L2 正则的含义，所以本次是共同任务下的模型适配比较，不能声称所有训练先验完全相同。

## 5. 运行和查看结果

正式命令：

```bash
conda activate ode
python -m paper_odeae.run_baselines
```

运行结果保存在 `paper_odeae/results/baselines_full/`。队列每 60 秒刷新 `summary.md` 与 `summary.json`，表中同时列出原 ODE-AE、Deterministic、LSTM 的 seed 0 结果。正在训练时只显示验证进度，测试列在任务完整结束后填写。

每个任务通过 SwanLab 记录批次损失、每轮验证指标、学习率、梯度和最终评价。物理 GPU、实际张量设备、数据 SHA256、参数量、锚点与时间单位另存于 `hardware.json`。

若已有同配置完整结果，队列核对配置及数据摘要后跳过。若有未完成历史，则停止并要求选择新的输出目录，避免覆盖已有记录。当前入口没有断点续训功能。

## 6. 启动前做了哪些检查

四个任务分别通过单轮 CUDA 小规模训练、验证选模、保存、重载和测试。另有三项适配检查覆盖类别反馈与掩码、未来值隔离及有限梯度、截止点锚定和填充处理。相关入口为：

```bash
CUDA_VISIBLE_DEVICES=2 python -m unittest paper_odeae.tests.test_baselines -v
python -m paper_odeae.run_baselines --smoke --output paper_odeae/results/baselines_smoke
```

小规模检查结果仅说明链路可运行，不作为正式效果。正式比较需等待完整任务结束，再读取各任务的 `metrics.json`。
