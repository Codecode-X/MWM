# ADNI 多模态纵向预测实验说明

这份文档从一位患者的随访记录出发，说明数据怎样变成模型输入、两种模型怎样学习，以及实验怎样评价预测结果。完整结果另见[结果报告](../results/adni_cuda/summary.md)，与参考论文的对照见[文献比较](../results/adni_cuda/paper_comparison.md)。

## 1. 我们希望模型回答什么问题

ADNI 持续收集患者的认知量表、脑部影像和生物标志物。不同检查的时间并不一致，每位患者拥有的检查种类也不同。

本实验要回答的问题是：给定一位患者已经完成的检查，能否预测他在后续随访中的检查数值？例如，一名患者整理后有六个随访时间点。在验证和测试时，模型读取前三个时间点的数据，然后预测后三个时间点的数值。

这里的预测时间由实际后续随访记录提供。也就是说，我们评价的是“在这些时间进行检查，数值会是多少”，而不是“患者什么时候会回来检查”。

实验比较仓库中的 Latent ODE 和 ODE-RNN。设计参考了 [Zanin 等人的 ODE-AE 工作](https://doi.org/10.1101/2025.08.26.672412)，主要借鉴患者级划分、季度聚合和利用不完整历史预测未来的思路。下面先说明本地实验的具体做法；与论文的差异放在文献比较中逐项展开。

## 2. 哪些患者进入了实验

### 2.1 数据从哪里读取

数据根目录为 `/data/SAMSUNG_backup/ADNI_data/`，其中 `ADNI_multimodal_timeline/` 保存按患者和日期整理的正式时间线。

程序先读取数据集说明和完整性验证结果，再读取患者清单与已有划分。每位患者的检查顺序由 `timeline.json` 指定，具体内容从对应日期的 `record.json` 读取。这样的读取方式使用了数据整理阶段确认的顺序。

### 2.2 为什么按患者划分

同一位患者的多次检查之间有很强的关联。如果把他的早期记录放入训练集、后期记录放入测试集，模型可能利用已经见过的个体信息获得较低误差。

因此，本实验沿用数据集已有的患者级划分。一位患者的全部记录只属于一个集合。训练集用来学习参数，验证集用来选择检查点，测试集在训练结束后用于评价。

### 2.3 为什么最后使用的患者比原始队列少

未来预测需要同时拥有历史和后续观测。本实验要求患者整理后至少有三个包含有效数值检查的季度，再构造历史与未来两部分。

| 集合 | 原始患者数 | 满足纵向实验条件的患者数 | 在实验中的作用 |
|---|---:|---:|---|
| 训练集 | 2,199 | 1,677 | 学习模型参数 |
| 验证集 | 420 | 312 | 选择每个任务的最优检查点 |
| 测试集 | 446 | 324 | 评价选定模型的预测误差 |
| 合计 | 3,065 | 2,313 | |

筛选依据是有效检查时间点是否足够，不使用诊断标签或检查数值的大小。由此得到的结果描述的是这批具有后续观测的患者。

## 3. 怎样把检查记录整理成数值序列

### 3.1 模型预测哪些数值

数值数据共保留 58 个字段。它们来自下列十类检查。

| 检查类别 | 主要字段或内容 | 表达的信息 |
|---|---|---|
| MMSE | 总分 | 总体认知表现 |
| CDR | CDR-SB、全局分及各分项 | 认知与日常功能受损程度 |
| ADAS | 总分、ADAS-13、各题分数 | 认知测验表现 |
| FAQ | 总分和各分项 | 日常活动能力 |
| 记忆及词语学习测验 | 即刻/延迟回忆、词语学习等 | 记忆表现 |
| 血浆 | pTau217、Aβ42、Aβ40、Aβ42/Aβ40、NfL、GFAP | 血液生物标志物 |
| 脑脊液（CSF） | Aβ40、Aβ42、tau、pTau | 脑脊液生物标志物 |
| 淀粉样 PET | Centiloids | 淀粉样蛋白负荷 |
| tau PET | 颞叶、内嗅皮质 SUVR | 特定脑区的示踪剂摄取 |
| MRI 定量结果 | 左右海马体积 | 脑结构测量 |

这些字段都是本次预测的目标。诊断标签、治疗记录和自由文本没有进入本次输入。

字段的名称、范围和来源定义在 [`src/adni_data.py`](../src/adni_data.py)。血浆字段保留各自检测平台的含义；CSF 使用 Roche Elecsys 数据。这样可以避免把不同检测方法产生的数值直接混为同一字段。

### 3.2 怎样处理检查日期

一次随访中的量表、影像和化验可能在不同日期完成。为了把邻近日期的检查组织成一个输入，程序以每位患者首次有效数值检查为起点，建立连续的 91.3125 天窗口，约等于一个季度。

同一窗口内，同一个字段如果有多次测量，就取均值。窗口的时间戳放在右边界，表示截至这个时间点，窗口内的检查都已发生。例如，窗口内第 10 天和第 40 天完成的两项检查，会在这个窗口结束时一起交给模型。

没有检查的窗口不会被补成一次随访。模型保留两个有效窗口之间的时间间隔，因此相隔三个月和相隔两年的记录会产生不同的时间演化。

没有日期、日期错位以及标为 `provisional` 的事件被排除。其余日期关联方式的计数保存在 `data/adni_cache/metadata.json`，便于追溯记录来自直接日期匹配还是访视代码关联。

### 3.3 怎样处理缺失和质控

一位患者可能只有量表而没有 PET。程序为每个字段同时保存“数值”和“是否真实观测到”的标记，这个标记称为缺失掩码。

如果某个字段缺失，计算用的数值位置暂放 0，掩码设为 0。模型和损失函数通过掩码识别这个位置，因此不会把它当作一次真实的零值检查。`-4` 等非法编码、非有限数、范围外数值，以及 `>1700` 这类只给出检测界限的结果，也按缺失处理。

PET 使用 `qc_flag=2` 的完全质控通过记录。淀粉样 PET 使用 Centiloids，是因为不同示踪剂的 SUVR 不宜直接混合。这里依照 [ADNI 的 PET 说明](https://adni.loni.usc.edu/quick-start-guide-asset/pet.html)使用采集日期组织数据；[Berkeley PET 方法](https://pmc.ncbi.nlm.nih.gov/articles/PMC11772732/)提供了质控评分的解释。

MRI 海马体积记录排除明确的质控失败项。源表中仍有质控未知或仅部分完成的记录，这些记录被保留，并在元数据中单独计数。因此，MRI 数值组包含不同质控状态的数据。

现有 FDG 表主要提供采集信息，缺少本协议需要的区域 SUVR。扫描剂量和扫描仪型号表达的是采集条件，所以没有被当作 FDG 生物标志物输入。

### 3.4 为什么还要标准化

量表分数、海马体积和化验浓度的单位不同。直接把这些误差相加，会让数值尺度较大的字段主导训练。

程序先用训练患者计算每个字段的均值和标准差，再把该字段转换为 z-score：

```text
标准化数值 =（原始数值 − 训练集均值）/ 训练集标准差
```

验证集和测试集沿用这套训练集参数。字段是否保留也只根据训练集判断：有效数值少于 100 个的字段被排除。完整的字段清单和归一化参数保存在 `data/adni_cache/metadata.json`。

## 4. 怎样增加原始 MRI 提供的信息

前面的 MRI 数值字段已经包含海马体积。接下来增加的 MRI 特征，来自对原始 T1 影像运行预训练神经网络。

这样得到两组输入：第一组使用 58 项数值特征；第二组在同样的数值特征上增加影像特征。两组保留相同的患者和预测目标，用来观察额外影像信息是否有帮助。

### 4.1 怎样选择编码器

影像编码器把三维图像转换为一组数字，这组数字称为影像表征或嵌入。选择时主要考察三点：是否适合三维医学图像、权重是否可取得、预训练数据是否有清楚的说明。

| 候选方案 | 调研中关注的特点 | 本次安排 |
|---|---|---|
| MedicalNet 原始 ResNet10 | 使用三维医学图像训练，公开八个预训练数据集的来源，含脑和海马分割数据 | 选作冻结编码器 |
| MedicalNet 23-dataset 版本 | 提供更多预训练数据，但额外数据的说明较少 | 保留为后续候选 |
| Brain-ID | 面向脑解剖表征，使用合成训练数据，提供权重和处理流程 | 需要另行适配密集特征和依赖，本次未运行 |
| BrainIAC | 面向脑 MRI，公开论文列出 ADNI 数据来源 | 需要先解决预训练患者与本地划分的重叠核查 |
| 自然图像二维编码器 | 权重容易获得，输入形式与三维 MRI 有较大差别 | 本次优先考察医学三维编码器 |

最后使用的是 [Med3D/MedicalNet](https://arxiv.org/abs/1904.00625) 原始 ResNet10。它的公开预训练来源中没有列出 ADNI；公开镜像没有患者级清单，所以这里依据的是数据集来源说明。

### 4.2 从一份 MRI 到 16 个输入特征

每位患者选择最早一份能够识别为 MPRAGE、SPGR 或 T1 的 MRI。选择顺序只依赖扫描日期和固定的影像标识。

影像依次经过以下处理：

1. 读取 DICOM 或 NIfTI。DICOM 切片按物理位置排序，并统一图像方向。
2. 截取非零区域，进行强度标准化，再重采样为 `96 × 96 × 96`。
3. 在 CUDA 上运行冻结的 MedicalNet。冻结表示其权重在本次实验中保持不变。
4. 对网络输出作全局平均池化，得到 512 维向量。
5. 使用训练患者的向量拟合主成分分析（PCA），压缩为 16 维，再用训练投影的标准差缩放。

本次没有执行颅骨剥离、MNI 非线性配准或编码器微调。上述流程定义了本次实际考察的影像表征方案。

### 4.3 MRI 在什么时候进入患者历史

MRI 特征放入扫描日期之后的第一个已有数值检查窗口。如果扫描发生在历史截止点之后，这份影像就不会进入该次预测的输入。

因此，影像特征在患者序列中有自己的可用时间。模型通过这条时间线使用它，而不是把一份后来拍摄的 MRI 复制到所有历史记录中。

### 4.4 实际有多少 MRI 可用

| 处理阶段 | 患者数 |
|---|---:|
| 纳入纵向实验 | 2,313 |
| 找到符合选择规则的 T1 | 2,301 |
| 成功提取影像特征 | 2,267 |
| 因切片不足排除 | 34 |
| 没有符合规则的 T1 | 12 |

影像文件齐全与临床图像质量是两件事。这里的提取检查主要确认文件可以组成可处理的三维输入；失败记录保存在 `data/adni_cache/encoder_failures_*.json`。

PCA 使用 1,643 名训练患者拟合。按固定的前半段历史划分，验证集有 299 人、测试集有 306 人能在截止点前获得影像特征。其余患者通过缺失掩码保留在实验中。

## 5. 两种模型分别怎样预测未来

### 5.1 先理解 ODE 在这里做什么

模型用一个隐藏状态概括患者已经提供的信息。常规递归网络主要在收到新检查时更新状态；ODE 则描述两次检查之间状态如何随时间连续变化。

这个状态是一组模型学习出的数字，不能直接等同于某个具体医学指标。模型再通过解码器，把状态转换为 MMSE、海马体积等预测值。

### 5.2 ODE-RNN 的处理过程

ODE-RNN 按时间顺序读取历史。两次检查之间，ODE 推进隐藏状态；收到新检查时，GRU 更新状态。GRU 是决定怎样结合旧状态和新观测的递归更新单元。

进入未来阶段后，模型不再读取真实检查值。它先预测下一个时间点，再把自己的预测反馈给状态更新过程，继续预测后面的时间点。

### 5.3 Latent ODE 的处理过程

Latent ODE 也先读取历史，但它接下来估计的是历史截止点处潜在状态的一个概率分布。本次分布使用高斯形式，由均值和标准差描述。

模型从这个分布抽取初始潜在状态，然后用生成 ODE 推进到未来，最后解码为各项检查的预测值。训练时抽样 3 次；验证和测试时抽样 8 次，把这些预测的均值作为点预测。

### 5.4 为什么增加容量匹配组

两种原生结构包含的计算模块不同，因此默认配置的参数量也不同。参数较多的模型可能拥有更强的拟合能力。

为考察这个因素，实验额外扩大 ODE-RNN，让它的预测网络参数量接近对应的 Latent ODE。这里统计参与预测的网络，不计本任务中闲置的诊断分类头。

| 输入 | Latent ODE 预测参数量 | 原生 ODE-RNN 预测参数量 | 扩大后 ODE-RNN 预测参数量 |
|---|---:|---:|---:|
| 数值特征 | 65,818 | 24,570 | 65,827 |
| 数值特征 + MRI | 72,490 | 28,170 | 72,476 |

两种输入各包含三种模型配置，因此一共有六组配置。每组使用五个随机种子独立训练，合计 30 个训练任务。

## 6. 一次训练怎样进行

### 6.1 先划分历史与未来

每一轮训练都会为每位患者随机选择一个截断点。截断点之前的检查构成历史，之后的检查构成预测目标。

为让模型适应检查缺失，训练时再随机遮掉 10% 的历史字段。预测误差只在真实存在的未来检查上计算。

ODE-RNN 在历史阶段使用 0.5 的 teacher forcing 概率：它有时读取真实历史检查值，有时使用自身预测。进入未来后，始终只使用模型预测。

### 6.2 再计算学习目标

两种模型都使用标准化后的平方误差。每个字段先只在其有效观测上平均，然后对字段取平均，使稀少模态也能参与学习。

Latent ODE 还包含一个 KL 项，用来约束它估计的潜在状态分布。该项除以潜在维度，最终系数为 0.001，并在前 10 轮逐步增加到完整权重。这是本次针对多模态预测采用的学习目标。

### 6.3 训练设置与检查点选择

| 设置 | 本次取值 |
|---|---|
| 每个任务的训练轮数 | 30 |
| 随机种子 | 0、1、2、3、4 |
| 批量大小 | 64 名患者 |
| 优化器 | Adam |
| 学习率 | 0.001 |
| weight decay | 0.00001 |
| 梯度裁剪上限 | 10 |
| Latent ODE 潜在维度 / 编码器隐藏维度 | 32 / 64 |
| 原生模型 ODE 网络 | 两层、每层 64 个神经元，Tanh 激活 |
| 扩大后 ODE-RNN：数值组 | latent=81，width=58 |
| 扩大后 ODE-RNN：MRI 增强组 | latent=81，width=49 |

每轮结束后，程序在验证集上评分，保存验证误差最低的检查点。验证时固定读取前 `floor(T/2)` 个有效窗口，其余窗口用于未来预测，其中 `T` 是该患者的有效窗口总数。

训练结束后，重新加载选定检查点，在验证集和测试集上评价。测试集不参与检查点选择。

30 轮构成本次统一的训练预算。实际结果中，许多最优检查点出现在接近第 30 轮的位置，因此本次比较描述的是这个训练预算下的表现。更长训练是否会改变排名，需要另外观察收敛过程。

## 7. 怎样读懂评价指标

### 7.1 标准化误差：用来汇总不同检查

主要指标叫作 z-score macro MSE，可理解为“标准化后，对各字段等权平均的平方误差”。它分两步计算：先计算每个字段在未来有效观测上的 MSE，再对有观测的字段取平均。

数值越低，代表平均预测误差越小。平方会放大较大的预测偏差，因此 MSE 对少量大误差比较敏感。

报告同时给出 macro MAE。MAE 使用绝对误差，能帮助观察整体偏差是否也随着 MSE 改善。

### 7.2 原始单位误差：用来理解量表分数

为了把统计量与实际检查联系起来，报告另外给出 MMSE、CDR-SB、ADAS-13 和 FAQ 的原始单位 MAE。

例如，MMSE 的 MAE 为 1.77，表示模型预测总分与实际总分的绝对差，平均约为 1.77 分。这比标准化误差更容易联系到某个具体量表，但不同量表的分数仍应分别理解。

### 7.3 持续值基线：用来判断预测是否有实际改进

患者的一些指标在短期内变化不大。因此，除了比较两个神经网络，还需要一个简单参照：把历史中最后一次检查值直接当作未来预测。

这就是持续值基线。若某个字段在历史中从未测过，则使用训练集均值。它没有需要训练的参数。

### 7.4 五个种子和差异区间分别表达什么

同一模型从不同随机初始化开始训练，结果会有波动。表格中的“均值 ± 样本标准差”描述五次训练的平均表现和波动大小。

比较两个模型时，我们还在相同患者上计算误差差值，并对患者与种子进行 2,000 次配对 bootstrap 重抽样，得到差值的 95% 区间。若区间跨过 0，说明在当前重抽样结果中，差异方向仍有不确定性。

这些统计围绕当前固定患者划分展开。它们表达模型比较的不确定性；患者未来轨迹的预测区间覆盖率则是另一项需要单独计算的指标。

### 7.5 为什么还按模态和时间跨度拆开报告

各模态的检查数量相差很大。总体误差之外，报告列出每类检查的误差和有效观测数，帮助读者辨认改善来自哪些字段。

时间跨度按距离历史截止点的 0–1 年、1–3 年、3 年以上划分。不同跨度中出现的患者和检查种类可能不同，因此阅读这些结果时，需要同时查看对应的观测数量。

## 8. 计算设备与数值检查

所有训练、编码器前向、验证和检查点评估都使用现有 Conda `ode` 环境与 CUDA。实际硬件是四张 RTX 4090，每张约 24 GB 显存，物理编号为 0–3。

训练任务按独立任务分配到 GPU。影像读取较慢时，冻结编码任务与小型预测训练并行运行。CPU 承担文件读取、影像解码、PCA、统计汇总与绘图。

ODE 使用批量 RK4 求解。程序以十年为一个计算时间单位，最大子步长为 0.05，即半年；较长的检查间隔会自动拆成多个子步。

程序还进行了两类数值核对。首先，在 CUDA 上比较 RK4 与仓库原有自适应 Dopri5 的结果。随后，对每个最优检查点把 RK4 步长减半，再计算验证误差。30 个任务中，步长减半导致的验证 macro MSE 最大变化约为 `9.32e-09`。

全部 30 个检查点还完成了独立重新加载核对，重算指标与已保存指标的差异均为 0。设备、参数量和核对结果分别保存在各任务的 `hardware.json` 与 `checkpoint_verification.json` 中。

## 9. 怎样重新运行

下面的命令从仓库根目录执行。首先启用环境、安装依赖，并取得已经固定版本和校验值的编码器权重：

```bash
source ~/miniforge3/etc/profile.d/conda.sh
conda activate ode
pip install -r requirements-adni.txt
python scripts/download_adni_encoder.py
```

接下来整理数值数据，选择 MRI，并在四张 GPU 上提取特征：

```bash
python -m src.adni_data
python -m src.adni_images --select
for gpu in 0 1 2 3; do
  CUDA_VISIBLE_DEVICES=$gpu python -m src.adni_images --shard $gpu \
    > results/adni_cuda/encoder_gpu${gpu}.log 2>&1 &
done
wait
python scripts/audit_adni_data.py
```

数据准备完成后，运行两种输入下的原生模型与容量匹配组。脚本会跳过配置相同且已经完成的任务。

```bash
python scripts/run_adni_experiments.py --epochs 30 --gpus 0 1 2 3
python scripts/run_adni_experiments.py --epochs 30 --gpus 0 1 2 3 --imaging
python scripts/run_adni_experiments.py --epochs 30 --gpus 0 1 2 3 --matched
python scripts/run_adni_experiments.py --epochs 30 --gpus 0 1 2 3 --imaging --matched
```

最后执行检查并生成结果报告：

```bash
CUDA_VISIBLE_DEVICES=0 python -m unittest tests.test_adni -v
python scripts/verify_adni_checkpoints.py
python scripts/summarize_adni.py
```
